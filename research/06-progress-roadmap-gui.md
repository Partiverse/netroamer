# netroamer 评估（六）：完成度盘点、功能逻辑树、未来路线与 GUI 决策

> 日期：2026-10-03。依据：v1.0.0 代码库实测盘点（17 个内部包、33 commits、
> 15 个测试包全绿）、72h 挂机验收报告（全部 PASS）、两轮对抗评审遗留项核对。
> 本文回答四个问题：现在到哪了｜还欠什么｜功能之间的逻辑关系｜GUI 做不做、怎么做。

---

## 0. 结论先行

1. **完成度：MVP 架构 100% 落地，生产验证分层明显。** 遥测/聚合/判定/行动/证据五层的代码与测试全部交付（judge 85%、health 78%、actuator 79.6% 覆盖率），但**自愈动作至今零次实战**——judgments 表为空。原因有二：影子模式未放权（设计如此）+ 资格闸全拦截且 allow 列表为空（设计保守但让卖点处于休眠态）。当前系统是「一辆测试场里全绿、还没上过公路的车」。
2. **最大的坑不在代码在分发**：v1.0.0 Release 没有预编译二进制，安装必须有 Go 工具链——对目标用户（中国开发者中的非 Go 群体）直接劝退。
3. **六个已核实的实现缺口**（对照 05 设计）：SSID 感知、直连规则「代理变优退出」、doctor 的 brew 供应链抽验、bootstrap 两段式+签名+--dry-run、watchdog kill-switch 迁移、动作链路生产实测。
4. **GUI：做，但做「本地 Web 控制台」而非原生菜单栏**。分两阶段：Phase A 只读观测（放权前的信任基础），Phase B 控制面（--actuate 的安全开关）。原生托盘推迟到 P3。理由与红线见 §5。

## 3. 软件功能逻辑树

### 3.1 三层分工（系统级）

```
netroamer 项目
├── bootstrap.sh / .ps1        【装好】一次性环境配置（rc/镜像/DNS 可选/规则模板/装 agent）
├── share/net-watchdog.sh      【活着】5min 生死探活（死了拉起、清系统代理）
└── netroamerd (Go agent)      【活好】秒级质量观测 + 自愈闭环 ← 本体
    ├── clash/ 模板            【挂载】Merge(provider 声明) + rules prepend(RULE-SET 行)
    └── research/              【蓝本】00–05 设计 + 06 本篇 + reviews/
```

三者红线一致：TUN 不开、不用 root、数据不出设备。

### 3.2 netroamerd 内部（数据流视角）

```
观测层（只读 mihomo + 主动探测，绝不注入流量）
├── collector ── WS /connections 每秒快照 → 连接生命周期 → samples（被动）
├── sampler  ── 30min × TOP20 域名 → 同口径探测 → probes(sampling)（补延迟缺口）
└── health   ── 60s 当前出口探测 + 事件驱动全组 → probes(health) → 节点健康分

数据层
└── store ── SQLite(WAL/0700/0600)
    ├── samples(7d)   被动连接样本（无延迟，只有计数与成败）
    ├── probes        主动探测（sampling/retest/health，含延迟与失败分类）
    ├── agg           桶×域名×路径 聚合（EWMA/P95 ← analyzer 5min 重算 + 回填）
    └── judgments     动作/回滚留档（配额/冷却/终态的事实源）

认知层（纯统计，判定输入 = agg + 实时探测）
├── analyzer ── 滚动聚合 + 从 probes 回填 ewma/p95
├── judge ── 慢域名判定
│   ├── 条件1 域名级初筛（≥50 样本 & ewma>800 或 p95>1500）
│   ├── 条件2 桶级方向验证（≥3 活跃桶同向）
│   ├── 条件3 同口径实时探测（direct < proxy×50%）
│   ├── 条件4a 资格闸（.cn/境内表/allow）  ← 正向白名单
│   ├── 条件4b 豁免闸（订阅规则非DIRECT命中 + exempt 文件） ← 负向硬闸
│   └── 状态机：配额7d2次 → 回滚冷却7d → 终态3次回滚永久通知；联动静默窗
└── health ── 坏节点判定（连续性：硬故障3败 / 劣化2次超EWMA+3×MAD）
    └── score=ewma×penalty → 滞回切换（×1.2 + 10min防抖） + 手动选择30min尊重

行动层（唯一改 mihomo 状态的地方，全部 --actuate 门控）
├── actuator ── 写自有 provider → PUT 热载 → ruleCount对账+RULE-SET行验证 → 失败还原
├── health.SelectProxy ── PUT /proxies/{group}（硬故障例外可越过手动窗口）
└── retest ── 24h 逐时直连复测 → 滑窗回滚（连3败/6中3败） → 终态计数

问责层
├── judgments ── 全部动作/回滚留档（params_hash 归因）
├── evidence ── 修复前后对照 JSON+Markdown
└── notify ── 系统通知（动作即通知）

生命周期与诊断
├── config（端点/secret 发现，强制环回）  ├── service（LaunchAgent/systemd）
├── install / uninstall --full（指纹清理） ├── doctor（七项自检+修复指令）
└── status / judge / rollback CLI
```

### 3.3 两条自愈路径的状态机

**慢域名直连**：`观测(agg慢) → 初筛 → 桶验证 → 资格闸 → 豁免闸 → 配额/冷却/终态/联动窗 → 同口径探测 → [影子:记录 | 实操:热载直连] → 24h复测 →(失败)→ 回滚 →(×3)→ 终态`

**坏节点切换**：`出口探测 → 连续性判坏 → 事件驱动全组 → 手动窗口检查 →(硬故障例外)→ 滞回比较 → [影子:记录 | 实操:PUT切换] → 联动静默窗(冻直连2h) → penalty 恢复期 →(新节点也坏)→ 再评估`

共同特征：**入口层层收窄（宁缺勿滥）、出口必须有路（复测/冷却/终态/恢复期）**——这正是两轮对抗评审后定稿的「有进有出」形态。

## 4. 未来开发路线

### P1.5 放权运营期（现在 → ~2 周，唯一优先级）

目标：让闭环**第一次真正转起来**。G1 是当前一切的核心——不实战，其余都是纸面完善。

1. allow 列表种子：挑 1–2 个用户确认直连更快的域名（如公司内网工具域、境内 CDN）写入 allow 文件；
2. LaunchAgent 加 `--actuate`，跑 3–5 天；
3. 复盘 `evidence/` + `judgments/` + 日志：热载成功率、误判率、通知体验；
4. 顺带做 **G2（Release 二进制）**——放权期发现的任何问题，修复版要能让非 Go 用户拿到。

**退出标准**：≥1 次真实直连动作 + 证据完整 + 无一例误判 → 具备对外传播条件。

### P2 观测与分发（~2–6 周）

1. **Web 控制台 Phase A/B**（见 §5）；
2. CI 三平台构建 + brew formula（G2）；
3. bootstrap 两段式 + 签名 + --dry-run（G6，与发布签名体系同期）；
4. 「代理变优退出」（G3）；
5. doctor brew 抽验（G5）。

### P3 智能与体验（~6–12 周）

1. SSID 感知（G4，桶精度）；
2. 统计升级评估：EWMA → 分位数回归/轻量本地模型（02 报告配方），**前提是 P1.5/P2 积累了足够 judgments 样本**——没数据不训模型；
3. 原生菜单栏壳（薄壳，内嵌 Web 控制台或直达浏览器）；
4. macOS 公证与签名（G6 延伸）；
5. watchdog kill-switch 迁移（G7）。

### P4 多端协同（远期，不承诺）

跨设备配置/证据同步——需要引入云端或 P2P，**违反「数据不出设备」红线的问题必须先有方案**（如仅局域网直连同步），否则不做。

### 不做清单（不变，防 scope creep）

诊断独立产品、通用传输加速、mesh、卖节点、订阅制、TUN/内核改动、自研传输协议、云遥测。

## 5. GUI 决策：做「本地 Web 控制台」，不做优先原生托盘

### 5.1 要不要 GUI？——要，但目的不是「操作」，是「信任与可观测」

「无感」北极星常被误读为「不需要界面」。正相反：**放权（--actuate）的前提是用户看见过 agent 的判断质量**。当前证据链（evidence/judgments/status）只有 CLI 出口，三个真实痛点：

1. **信任断层**：用户手改 plist 才能放权，之前看不见 agent 在想什么（judge 的 1323 次跳过判定只存在于日志里）；
2. **allow/exempt 管理原始**：手编文本文件，出错无提示；
3. **证据不可浏览**：修复前后对照生成了，但没人在意它们。

### 5.2 形态选择：为什么是内嵌 Web 而不是原生菜单栏

| 方案 | 评价 |
|---|---|
| **内嵌 Web 控制台（推荐）** | Go `embed` 单页应用打进现有二进制；`netroamerd ui` 或常驻自带 `127.0.0.1:7790`；与 mihomo 生态惯例一致（yacd/metacubexd 就是 web 面板，用户零学习成本）；跨平台一份代码 |
| 原生菜单栏（Wails/Systray） | 体验好但三平台维护重、签名公证链条长；对「无感」产品是奢侈品 → P3 做薄壳 |
| TUI | 开发者自嗨，不解决信任问题 |
| Electron | 违反形态约束（内存/体积），否决 |

### 5.3 分阶段范围

**Phase A——只读观测（先做，直接服务放权决策）**
- 延迟矩阵热力视图（agg：域名 × direct/proxy × 时段）；
- 自愈时间线（judgments 流 + 影子建议流，含每次跳过原因）；
- 证据浏览器（evidence Markdown 渲染 + 修复前后对照图）；
- 节点健康板（各 Selector 组当前 score/penalty/连续失败）；
- doctor 一键运行与结果展示。

**Phase B——控制面（每项写操作都显式确认 + 落 judgments）**
- 影子/实操模式开关（替代手改 plist——这本身就是一个安全改进）；
- allow/exempt 列表管理（增删改 + 变更审计）；
- 暂停窗口（「接下来 2h 别动我的网络」）；
- rollback 按钮（列最近动作、一键撤销）。

### 5.4 安全红线（GUI 是特权控制面，04 报告的 RCE 教训自己不能犯）

1. **只绑 127.0.0.1**（Unix socket 可选更稳）；首次启动生成随机 token 打印到终端，写操作必须带 `Authorization` 头；
2. **无宽 CORS**、写接口拒绝跨源表单（CSRF：要求自定义头 + token）；
3. 写操作全部进 judgments（GUI 动作与 agent 动作同一问责通道）；
4. doctor 已有的「external-controller 裸奔检测」逻辑复用为对自检——自己监听面必须在环回；
5. 控制台不展示 secret、不提供读订阅内容入口（隐私边界不因 GUI 改变）。

### 5.5 工作量估计

Phase A：后端 4 个只读 JSON 端点（SQLite + 现有 API 复用）+ 前端单页（无框架 vanilla/轻量 Preact，embed）≈ **3–4 人日**；Phase B ≈ **3–5 人日**（确认流与审计是大头）。在 P2 排期内可容纳。

## 6. 一页决策摘要

- **现在**：v1.0.0 影子模式验收全绿 → 立即进入 P1.5 放权试运行（allow 种子 + --actuate），这是唯一挡在「产品成立」前面的门；
- **接着**：P2 = Web 控制台（A→B）+ 三平台二进制 + 签名分发 + 变优退出；
- **GUI 答案**：做本地 Web 控制台，Phase A 先行——它不是锦上添花，是 `--actuate` 放权的安全前提与信任基础设施；
- **红线不动**：TUN/无 root/不出设备/宁缺勿滥/可回滚，GUI 与后续一切功能都在这五条之内。
